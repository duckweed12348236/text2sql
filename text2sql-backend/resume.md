# Text2SQL 智能问数平台（后端 / RAG + Agent）**技术栈**：Python、FastAPI（SSE）、LangGraph、Qdrant、PostgreSQL、MySQL、Redis Stack、Celery、BGE 向量模型、Qwen3-Reranker、Ragas- **采集**：表注释缺失、结构持续变更导致模型编字段 —— 脚本抽真实表结构、模型只补语义（描述/同义词/角色）并丢弃幻觉字段，用外键加 LLM 识别可 JOIN 字段建关系图，定时巡检增量重采，保证元数据与库结构一致。- **检索**：中文口语与字段命名对不上、固定 TopK 要么带噪音要么漏关键表 —— ① 查询侧用 jieba 加词性白名单抽关键词（省掉关键词扩展的模型调用），多关键词一次批量召回后按主键去重，并以原问题整句兜底防漏抽；② 索引侧把表名、表描述、字段名、别名、描述拼成一条文档整体向量化，一次检索覆盖多种说法且避免同字段多点；③ 按 BGE 不对称训练口径仅查询侧追加指令前缀，向量库按业务库隔离、payload 只存主键、内容回元数据库取，避免双写不一致；④ 召回后交 Cross-Encoder 重排，再按分差断崖动态截断（分差 ≥0.5 或落差 ≥25%，上限 20），最后由 LLM 语义过滤、只接受真实表 id，兼顾精度与上下文成本；⑤ 指标与字段双路并行检索并在汇合处校验口径。**在此基础上做资产自更新**：指标口径缺失时反问用户，回答审核通过即落库并向量化，下次直接召回；SQL 执行后取结果前几行自查，判定答非所问就按字段编号回写涉事字段的描述与别名并重新向量化，让同类问题下次按新语义命中；关联关系则按每轮真正用到的表增量识别，按字段编号双向登记、唯一约束幂等去重且只增不删，新识别的留给下一轮；字段描述或别名一旦变更就按字段整条清空其关系，由下一轮按新语义重新识别，避免用旧语义拼出错误 JOIN。**再配合字段多次召回**：自查不通过时用模型改写的问题与新关键词回跳到字段召回，重新召回、重排并重写 SQL，指标沿用上一轮已核对的口径，最多回退 5 次并重置 SQL 纠错预算，使检索能依据真实数据自我纠偏。- **评估**：优化缺乏客观依据 —— LLM 出题并校验参考 SQL 生成可复现数据集，用 Ragas 语义等价指标打分，同时留存检索上下文做 badcase 归因，形成「评测 → 改检索 → 再评测」的闭环。- **短期记忆**：多轮澄清与会话续跑需要跨请求保留上下文 —— 基于 LangGraph checkpointer 按 `thread_id` 持久化会话状态，`interrupt` 挂起反问、`resume` 接续执行；Redis 作一级缓存扛高频读写、PostgreSQL 兜底一致性，缓存异常降级直读数据库，不阻断主流程。
